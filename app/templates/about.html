About

Tripura Explore prototype

A working tourism discovery and trip-planning prototype for Tripura, India: {{ published_count }} published destinations, {{ categories|length }} categories, {{ districts|length }} districts, an interactive map, a rule-based trip planner, saved trips, a local-experience directory and an administrator dashboard.

Data and verification policy

The prototype follows four rules that come from the project's data-collection report:

  1. One record per destination. The homepage, Explore page, map, planner and details page all read the same database row, so a fact is never typed twice.
  2. Unknown stays unknown. Entry fees, opening hours, closed days and best seasons are left blank until the managing authority confirms them. Unknown values are shown as “Not verified”.
  3. Coordinates are labelled. Approximate coordinates are marked “approximate” on the map and on the details page. Distances are straight-line estimates, never claimed as road distances.
  4. Demo content is labelled. Provider listings, cultural descriptions and the illustrations are prototype placeholders and say so on screen.

What still has to be verified

  • District assignment for each destination, using official district records.
  • Field GPS coordinates for the main entrance of every destination.
  • Entry fees, camera and vehicle charges, opening hours, closed days and seasonal changes.
  • Licensed photographs, with credit and licence recorded per image.
  • Approved local providers, verified contact details and indicative prices.
  • Community review of every cultural description before publication.

See docs/DATA-VERIFICATION.md in the repository for the working checklist.

How the trip planner decides

  1. Validate the duration (1–3 days), start point and interests.
  2. Select published destinations whose category or tags match the interests.
  3. Rank them by interest matches and popularity, preferring records with coordinates.
  4. Group them by straight-line proximity (45 km) or by district when coordinates are missing.
  5. Spread the groups over the requested days, maximum three stops per day.
{{ icon("alert", 18) }} No route optimisation and no travel-time estimates are produced. Directions links open an external navigation service so you can check real driving times.

Known limitations of this build

Placeholder imagery

Destination pictures are generated illustrations. Licensed photographs still have to be collected.

No prices or hours

Fees, timings and typical visit lengths are blank until they are verified, so the planner cannot estimate cost or time.

Approximate coordinates

Map markers use approximate coordinates flagged in the interface; field GPS readings are still outstanding.

Demo providers

The experience directory contains demo listings, not real businesses. No bookings or payments exist.

No reviews or ratings

Reviews need moderation and abuse prevention, so no rating is displayed anywhere in the product.

Public tile server

OpenStreetMap tiles are used for the prototype. Production needs a dedicated tile provider.
